### 1.1 原始需求复述

实时扫描加密货币与股票行情，发现交易机会，并支持模拟盘（paper trading）验证策略，为未来实盘打基础。

### 1.2 已确认需求基线（用户拍板，PRD 以此为准）

| # | 决策 | 说明 |
|---|---|---|
| B1 | 接入市场：加密货币 + A股 + 美股，三个市场全要 | 分阶段接入，P0 先加密货币 |
| B2 | 界面路线：先 CLI 终端界面（rich/textual 风格）验证链路，稳定后再上 Web 看板 | P0 不涉及 Web |
| B3 | 模拟盘双模式：① 信号自动下单；② 仅告警、人工确认后再模拟下单 | 模拟盘引擎为 P1 |
| B4 | 工程铁律（AGENT.md）：每次改动必须建立对应 Git commit；每次改动必须编写/更新测试，交付前测试全部通过 | 所有阶段适用 |

### 1.3 已验证技术事实（架构设计输入，不可推翻）

| 项 | 结论 |
|---|---|
| 加密货币 | Binance 主域名（api.binance.com）本机被墙；**data-api.binance.vision（REST）与 data-stream.binance.vision（WebSocket）可用**，已实测收到 BTC 实时成交流水。OKX DNS 解析失败，不可用 |
| A股 | 东方财富 push2 API、新浪 hq.sinajs.cn 可用（约 3 秒级轮询），已实测返回 1642 只深主板实时行情 |
| 美股/港股 | 腾讯 qt.gtimg.cn 可用；美股为延迟数据（约 15 分钟级，免费源极限）。Yahoo Finance 被 consent 页挡住，不可用 |
| 网络 | 所有外网请求必须走本地代理；WebSocket 库需显式传 proxy 参数 |
| 环境 | pip 安装须用阿里云镜像（官方源 wheel 下载卡死） |
| 备选 | akshare 库可作 A股/港美股备选数据源，历史数据阶段可评估引入（其加密货币接口走 Binance 主域名，不可用） |

## 2. 产品定义

### 2.1 产品目标（3 个，相互正交）

| # | 目标 | 成功标准（可度量） |
|---|---|---|
| G1 | **稳定接入实时行情**：第 1 阶段建立 7×24 稳定的币安行情通道 | WS 连续运行 24h 无崩溃；断线后 10s 内自动重连成功；消息丢失率 < 0.1% |
| G2 | **及时发现交易机会**：内置可配置扫描规则，规则触发到告警输出延迟 < 2s | 至少 4 条规则可独立开关、参数可配；每条规则有单元测试与真实行情触发样例 |
| G3 | **验证策略闭环**：模拟盘完整记录"信号 → 下单 → 成交 → 持仓 → 盈亏"，支持复盘 | 双模式可切换；模拟盘数据可按标的/规则/时间回放；核心模块测试覆盖率 ≥ 80% |

### 2.2 用户故事（角色：个人量化交易者）

| # | 用户故事 |
|---|---|
| US-1 | As a 个人量化交易者，I want 在终端实时看到加密货币行情与异动告警，so that 我不用同时盯多个交易所 App 也能第一时间发现机会 |
| US-2 | As a 个人量化交易者，I want 自由启用/禁用扫描规则并调整参数（涨跌幅阈值、RSI 区间、均线周期），so that 我能按自己的策略过滤噪音信号 |
| US-3 | As a 个人量化交易者，I want 在"仅告警 + 人工确认"模式下验证信号后再模拟下单，so that 我能检验策略而不被自动交易干扰 |
| US-4 | As a 个人量化交易者，I want 查看模拟盘的成交、持仓与盈亏记录并复盘，so that 我能评估策略表现、决定是否走向实盘 |
| US-5 | As a 个人量化交易者，I want 后续同时监控 A股/美股行情，so that 我能跨市场发现机会（第 2-3 阶段） |

### 2.3 UI 设计草案（CLI 优先，P0）

```

│ 状态栏: [WS●已连接 12m] [代理 127.0.0.1:xxxx] [规则 4/4 开] │

│ 币种   最新价     涨跌幅%   成交量      信号               │
│ BTC   68,432.10  +2.31    12,450      ⚡成交量突增        │
│ ETH    2,455.8   -0.82     8,210       —                 │
│ SOL     172.35   +5.12     1,890      ⚡价格异动/RSI超买  │
├──────────────────────────────────────────────────────────┤
│ 告警日志（滚动）                                            │
│ [14:32:05] SOL 触发 价格异动(+5.12%/5min) 阈值5%          │
```

- 技术：rich Live 面板（或 textual TUI），数据流与渲染分离，渲染不阻塞行情处理
- 交互命令（键盘）：`r` 规则开关面板、`p` 暂停/恢复扫描、`q` 退出；后续 Web 看板复用同一数据层

## 3. 技术规范

### 3.1 需求池（P0 / P1 / P2）

#### P0 —— 第 1 阶段必须

| # | 需求 | 验收标准 |
|---|---|---|
| P0-1 | **币安 WS 适配器**：连接 `data-stream.binance.vision`（显式走本地代理），订阅主流币实时行情流；断线指数退避自动重连；心跳/超时监测 | 24h 压测无崩溃；断线 10s 内重连；有集成测试（可用录制数据回放） |
| P0-2 | **币安 REST 客户端**：`data-api.binance.vision` 获取 K 线/历史数据，供指标计算；代理、超时统一配置 | 单元测试覆盖请求构造与异常重试；配置项集中在 `config/` |
| P0-3 | **指标计算模块**：基于 pandas-ta 实现 RSI、MA（短期/长期）、成交量均量；数据用环形缓冲管理窗口 | 典型行情序列单元测试；指标值与 pandas-ta 参考实现一致 |
| P0-4 | **扫描规则引擎**：① 价格异动（N 分钟涨跌幅超阈值）② 成交量突增（> N 倍均量）③ RSI 超买(>70)/超卖(<30) ④ 均线金叉/死叉；规则可插拔、参数可配、独立开关 | 每条规则有单元测试 + 触发样例；引擎到告警延迟 < 2s |
| P0-5 | **rich 终端实时看板**：行情表 + 告警日志 + 连接状态栏；刷新周期 < 1s | 手工验收截图可用；规则开关/暂停操作不阻塞数据流 |
| P0-6 | **告警输出**：终端高亮 + 告警日志文件；告警含币种、规则名、触发值、阈值、时间戳；支持按规则过滤 | 告警可导出（CSV/JSON）；无重复轰炸（同币种同规则冷却时间可配） |
| P0-7 | **工程基线**：配置文件（代理、币种清单、规则参数）与代码分离；`.env` 管理敏感项；Git commit 规范落地（遵循 AGENT.md） | 首次提交含完整可运行骨架；CI/本地 `pytest` 全绿方可交付 |
| P0-8 | **测试体系**：适配器/规则/指标全部可测（mock 外部 IO）；交付前 100% 通过 | 覆盖率 ≥ 80%（指标与规则核心逻辑优先） |

#### P1 —— 第 2-3 阶段

| # | 需求 | 验收标准 |
|---|---|---|
| P1-1 | **A股适配器**：东方财富 push2 + 新浪 hq.sinajs.cn，约 3s 轮询；覆盖自选/热门标的 | 轮询稳定运行 24h；行情字段完整（价、量、时间） |
| P1-2 | **美股/港股适配器**：腾讯 qt.gtimg.cn；界面明确标注"数据延迟约 15 分钟" | 延迟标注在 UI 与告警中可见 |
| P1-3 | **模拟盘引擎**：虚拟账户 + 手续费/滑点可配置；信号→下单→成交→持仓→盈亏全链路；双模式（① 信号自动下单 ② 仅告警、人工确认后下单）可切换 | 一笔完整交易链路可回放；双模式均有测试覆盖 |
| P1-4 | **信号记录与复盘**：信号/成交/持仓持久化；支持按标的、规则、时间查询回放 | 复盘查询 API/CLI 可用 |
| P1-5 | **规则扩展机制**：支持新增规则不改引擎核心（配置化或插件化） | 新增 1 条自定义规则仅需新增文件/配置 |
| P1-6 | **历史数据评估**：评估 akshare 或自建存储，支撑后续回测 | 输出评估结论（来源可用性、字段完整性、存储成本） |

#### P2 —— 未来

| # | 需求 |
|---|---|
| P2-1 | Web 看板（复用 CLI 数据层，前后端分离），多终端访问 |
| P2-2 | 实盘对接：交易所 API、密钥安全管理、风控与限额、人工审批闸门 |
| P2-3 | 策略回测引擎（基于 P1-6 历史数据） |
| P2-4 | 通知渠道扩展（邮件 / Telegram / 企业微信） |
| P2-5 | 多策略组合与绩效归因分析 |

### 3.2 关键工程约束（架构师必须遵守）

1. **网络**：所有外网请求（REST + WS）必须走本地代理；`websockets` 库显式传 proxy 参数；代理配置集中在配置文件
2. **数据源**：币安只用 `.vision` 域名；OKX / Yahoo Finance / Binance 主域名禁用
3. **测试**：外部 IO 全部 mock/录制回放，禁止测试依赖真实网络
4. **Git**：每次改动对应 commit；交付前 `pytest` 全绿（AGENT.md 铁律）
5. **延迟认知**：美股/港股为 15 分钟级延迟数据，规则触发语义需与数据频率匹配，不得承诺实时性

|---|---|---|
| M1（第 1 阶段） | P0-1 ~ P0-8 | 币安 WS 稳定 + 看板实时 + 4 规则告警 + 测试全绿 |
| M2（第 2 阶段） | P1-1 ~ P1-4 | A股/美股接入 + 模拟盘闭环 + 复盘可用 |
| M3（第 3 阶段） | P1-5 ~ P1-6 + P2 启动 | 规则可扩展 + 历史数据方案落地 + Web 看板立项 |

## 4. 待确认问题（需用户拍板）

| # | 问题 | 产品建议（默认按建议执行，除非用户否决） |

| Q7 | 模拟盘初始虚拟资金与计价货币？ | 默认每市场 100,000 单位计价货币（USDT / CNY / USD），可配置 |
